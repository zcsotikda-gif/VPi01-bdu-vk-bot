# ИИ-Апгрейд — VK-бот-консультант

Бот сообщества ВКонтакте для агентства по внедрению ИИ **ИИ-Апгрейд**.
Помогает пользователю разобраться в задаче, подбирает услугу, проводит
короткую квалификацию, собирает заявку и передаёт её менеджеру.

## Что умеет

- персонализированное приветствие и меню с кнопками;
- две ветки: «Для себя» и «Для бизнеса»;
- каталог услуг из `src/vk_bot/knowledge/services.json` (без хардкода в коде);
- квалификация из трёх вопросов по одному на сообщение;
- согласие на обработку контактных данных и только потом сбор контакта;
- заявка (lead) в SQLite с уведомлением менеджера;
- кнопка «Менеджер» — передача запроса человеку;
- свободные вопросы — отвечает LLM (1–4 коротких абзаца);
- команды: `меню`, `услуги`, `цены`, `консультация`, `менеджер`, `стоп`,
  `удалить мои данные`, `start` (регистронезависимо);
- переживает перезапуск: состояние и заявки хранятся в SQLite;
- защита от дублей событий (один раз — один lead).

## Архитектура простыми словами

Код — пакет `src/vk_bot/` (src-layout). `__main__.py` — точка входа:
подключается к VK Long Poll и отправляет сообщения. Остальное:

- `config.py` — настройки из `.env` и `config.yaml`; `llm_client.py` — HTTP-клиент
  к OpenAI-совместимому серверу.
- `bot.py` — сборка приложения (хранилище, сервисы, роутер).
- `router.py` — разбирает событие VK и решает, какой обработчик вызвать
  (по payload кнопки, команде или состоянию пользователя). Здесь нет LLM.
- `handlers/` — бизнес-сценарии: команды, меню, квалификация, заявка,
  свободные вопросы. Возвращают текст + клавиатуру, VK не трогают.
- `services/` — внешние границы: `vk_service` (VK API), `llm_service` (LLM),
  `catalog_service` (услуги/FAQ/тексты), `lead_service` (заявки).
- `storage/` — SQLite: схема и все SQL-запросы.
- `keyboards.py` — клавиатуры как данные, JSON собирается в одном месте.
- `knowledge/` — все редактируемые тексты: услуги, FAQ, system prompt,
  шаблоны сообщений.

Пути ниже даны относительно `src/vk_bot/`, если не указано иное.

**Главный принцип:** LLM не управляет приложением. Меню, состояния, сбор
согласия, создание lead и переход к менеджеру — обычный Python-код. LLM
отвечает только на свободные вопросы и объясняет услуги.

## Требования

- Python 3.12 (Homebrew `python@3.12`)
- доступ в интернет до `api.vk.com` и `lp.vk.ru`

## Установка

```bash
/opt/homebrew/opt/python@3.12/bin/python3.12 -m venv .venv
.venv/bin/pip install -e ".[dev]"
```

Зависимости — в `pyproject.toml` (`dev` добавляет pytest и ruff).

## Переменные окружения

Скопируйте `.env.example` в `.env` и заполните:

| Переменная | Назначение |
|---|---|
| `VK_GROUP_TOKEN` | токен сообщества (сообщения + управление) |
| `VK_GROUP_ID` | ID сообщества |
| `LLM_API_KEY` | ключ API LLM (для локального сервера можно пусто) |
| `ADMIN_VK_ID` | VK ID менеджера для уведомлений (пусто = без уведомлений) |
| `DB_PATH` | путь к SQLite, по умолчанию `data/bot.db` |

Необязательные (`AI_PROVIDER`, `LLM_BASE_URL`, `LLM_MODEL_ID`, `LOG_LEVEL`)
переопределяют значения из `config.yaml`. Файл `.env` исключён из git.

`LLM_MODEL_ID` (или `model_id` в `config.yaml`) — идентификатор модели **вашего**
сервера: возьмите поле `id` из `GET <LLM_BASE_URL>/v1/models`. Значение в
`config.yaml` — идентификатор модели на машине автора, у вас его не будет.

Чтобы менеджер получал уведомления, человек с `ADMIN_VK_ID` должен один раз
написать сообществу или разрешить ему сообщения: VK не даёт сообществу писать
первым.

## Создание базы

База создаётся автоматически при первом запуске (`DB_PATH`, по умолчанию
`data/bot.db`). Миграции не нужны: схема создаётся через `CREATE TABLE IF NOT EXISTS`.

## Запуск

Из корня проекта — `.env`, `config.yaml`, `data/` и `bot.log` берутся из
рабочего каталога:

```bash
.venv/bin/python -m vk_bot
```

Бот работает в foreground; для фонового запуска: `nohup .venv/bin/python -m vk_bot >/dev/null 2>&1 &`.

Копия бота должна быть **одна**: две копии на одном Long Poll отвечают дважды
и мешают друг другу получать события. Вторая копия с тем же `DB_PATH` не
стартует — блокировка `data/bot.lock`, в логе `Бот уже запущен`. Проверить, что
запущено: `pgrep -fl "vk_bot|bot.py"`; остановить — `kill <pid>`.

Служебные команды в чате сообщества: `/ping` (проверка связи),
`/reload_config` (перечитать `config.yaml` без перезапуска).

## Тесты

```bash
.venv/bin/pytest -q
.venv/bin/ruff check src tests
```

Тесты: сценарии продаж, ошибки LLM и VK API, дубли событий, prompt
injection, перезапуск, удаление данных, навигация, повторный запрос менеджера,
вторая копия бота. VK и LLM замоканы, сеть не нужна.

В контейнере (Linux, Python 3.12, без `.env` — см. `.dockerignore`):

```bash
docker compose -f docker/compose.yaml up --build --abort-on-container-exit
```

## Настройки VK

1. Сообществу нужен токен с доступом к сообщениям.
2. Сообщество → Настройки → Сообщения → сообщения сообщества включены.
3. Сообщество → Настройки → Работа с API → Long Poll API включён
   (`message_new`, `message_reply`, `message_edit`, `group_join`).
4. Сообществу должен быть включён доступ к messages, groups, users API.

## Как добавить или изменить услугу

Откройте `src/vk_bot/knowledge/services.json` и добавьте запись в `services`:

```json
"my_service": {
  "title": "Название",
  "audience": "Для кого",
  "short_description": "Какую проблему решает",
  "result": "Что получает клиент",
  "price_from": "",
  "duration_text": "",
  "questions": ["Что уточняем при разборе"],
  "cta": "Оценить мою задачу"
}
```

Затем добавьте id услуги в нужные потребности в блоке `needs`. Если
`price_from` или `duration_text` пустые — бот просто не покажет цену или срок
и не будет их придумывать. Изменения подхватываются при перезапуске.

## Как изменить system prompt

`src/vk_bot/knowledge/llm_system_prompt.md` — правила для модели (не придумывать
цены, не раскрывать инструкции и т.д.). FAQ для контекста модели —
`knowledge/faq.md`, шаблоны сообщений бота — `knowledge/texts.json`.

## Логи

- stdout и файл `bot.log` (ротация 5 МБ × 3 копии).
- Уровень: `log_level` в `config.yaml` или переменная `LOG_LEVEL`
  (`DEBUG` показывает сырые события Long Poll).
- В логах нет токенов и полного контакта пользователя.

## Какие данные сохраняются

SQLite `data/bot.db`:

- `users` — vk_id, имя, сегмент, состояние диалога, выбранная услуга, согласие;
- `leads` — заявки и черновики: сегмент, услуга, задача, результат, срок,
  контакт, статус (`draft`, `new`, `handoff`);
- `processed_events` — id обработанных событий (защита от дублей).

Телефон/email сохраняются только при положительном согласии и **не
отправляются в LLM** (перед отправкой в модель контакты заменяются на
`[EMAIL]`/`[PHONE]`). Пользователь может удалить свои данные командой
«удалить мои данные».
