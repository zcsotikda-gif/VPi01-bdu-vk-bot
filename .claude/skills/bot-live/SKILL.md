# Живой прогон vk-bot

Бот работает с настоящим сообществом: каждое действие видят люди. Запуск и
остановка — по просьбе владельца.

## 1. До запуска
- Копия должна быть одна. Все процессы с рабочими каталогами:
  `pgrep -f "vk_bot|bot.py"` → для каждого pid `lsof -a -p <pid> -d cwd -Fn`.
  Чужой проект (другой cwd) не трогать. Старую копию этого бота — остановить
  только с согласия владельца: 20.10.2026 вторая копия из старого `venv`
  перехватывала Long Poll, и бот перестал получать события.
  Вторую копию с тем же `DB_PATH` не пустит `data/bot.lock`, но копию с другим
  `DB_PATH` или старым кодом блокировка не видит.
- `.env` не читать (запрет в `permissions.deny`). Задан ли `ADMIN_VK_ID`, видно
  после запуска по строке лога `admin=не задан`. Без него уведомлений менеджеру нет
  — попросить владельца вписать VK ID; человек с этим ID должен разрешить
  сообщения сообщества.

## 2. Запуск
Из корня проекта, в фоне: `exec .venv/bin/python -m vk_bot`.
Успех — в выводе `[INFO] vk_bot: Запуск бота` и `Starting BotPolling`, ошибок 0.

## 3. Чтение лога
Строки содержат VK ID и могут содержать контакт. В контекст — только маскированное:

    awk 'NR>N' <вывод> | grep -E '^[0-9]{4}-' | cut -d' ' -f2- \
      | sed -E -e 's/[^ ]+@[^ ]+/[EMAIL]/g' -e 's/\+?[0-9][0-9 ()-]{5,}[0-9]/#/g'

Рядом всегда счётчик ошибок: `grep -cE '\[(ERROR|WARNING)\]|Traceback'`.
Первое сообщение нового пользователя не пишет «Событие обработано» (ветка NEW в
`router.py`) — смотреть «Создан профиль» и «Команда start».

## 4. Нет событий
Порядок: процесс жив (`ps -p`) → вторая копия (шаг 1) → соединение с VK
(`lsof -a -p <pid> -i`) → только потом `LOG_LEVEL=DEBUG` (пишет сырые события с
текстом сообщений; спросить владельца).

## 5. Остановка
`kill <pid>`, затем `ps -p <pid>` → код 1 значит процесс завершён.
Фоновая задача при этом закончится с ненулевым кодом — это ожидаемо.
